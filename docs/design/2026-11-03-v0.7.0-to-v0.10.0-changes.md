## 2. v0.7.0 — PEAD event table v2

- The 13 v1 columns are unchanged in name, order, values and skip rules. 29 columns are
  appended: `acceptance_time_et`, `announce_timing` (`pre_open` / `market_hours` /
  `post_close`), `pre_announcement_session` / `reaction_session`, the day-0 straddle
  details that were previously computed and discarded, a second straddle priced at the
  last session before the news (`pre_*`), `implied_move`, `ret_reaction`,
  `surprise_ratio`, and `cik` / `cik_source`.
- A new column that can't be computed is left missing; it never removes a row.
- `build_pead_panel(start, end, index_id="sp500")` builds the table across the index,
  keeping an event only if the ticker was a member at the close before the news. One
  ticker's failure is recorded in the report and never stops the rest. It also takes a
  `tickers` subset, `cik_overrides`, and a `cik_resolver` hook (filled in by v0.10.0).

## 3. v0.8.0 — earnings surprise (SUE) from SEC XBRL

- `EdgarSource.company_concept(cik, tag)` reads SEC's per-company XBRL facts. A 404
  (the company never reported the tag) returns an empty frame.
- `fundamentals/sue.py`:
  - `quarterly_sue` keeps only the **first-reported** value for each period (earliest
    `filed`), so later restatements can never leak in. Diluted EPS is read from
    `EarningsPerShareDiluted`, falling back to `EarningsPerShareBasicAndDiluted`.
  - EPS is rescaled across splits for the math, but stored on each quarter's own
    as-filed basis, so stored values never change when a later split happens.
  - A missing Q4 is derived as full year − (Q1+Q2+Q3) and flagged `derived=True`.
  - SUE = (EPS_q − EPS_{q−4}) / std of the previous 8 year-over-year changes (at least
    6), using only filings that existed on the day quarter q was first filed.
  - `attach_sue` matches each event to the latest quarter that ended within 100 days
    before it and was first filed no earlier than 7 days before it. `eps_filed` can fall
    after the event; filter on it for a strict point-in-time backtest.
- `include_sue=True` on `build_pead_events` / `build_pead_panel` appends the 8 SUE
  columns. It is off by default, so default outputs and request counts are unchanged.
- Bugs fixed in review before the commit:
  - A missing split factor on Q1–Q3 made a derived Q4 silently wrong (2.0 instead of
    1.0 in the repro). It is now missing.
  - Identical year-over-year changes produced a SUE of about 10^15 from float noise.
    Below a 1e-9 relative floor the spread is now reported as 0 and SUE as missing.
  - Duplicate filings of the same quarter with a shifted start date blocked Q4
    derivation. Quarters are now deduplicated before deriving.

## 4. v0.9.0 — durable raw store and validation flags

- `StoreBackedSource(upstream)` (opt-in) saves daily split-adjusted bars, raw bars,
  index bars and dividends under `<data_dir>/raw/`, one parquet file plus a JSON
  manifest per (dataset, ticker). Each date range is downloaded once and reused across
  calls, processes and reruns.
- A session is saved only from 06:00 ET the next calendar day. Anything newer is fetched
  live on every call and never saved.
- Gaps are filled with one upstream request covering all of them. Not-entitled and empty
  results are recorded separately, and empty ranges aren't re-requested.
- If a later split changes the vendor's split-adjusted history, the overlap check sees
  it and the saved history is re-downloaded (`rebased=True`).
- Dividends are saved only on the raw cash basis. A store directory written by one
  vendor family refuses to serve a different one.
- Outputs match the upstream exactly: total-return bars are still composed per window,
  through the new shared `adjust.TotalReturnMixin`.
- In the acceptance test, a precompute over 3 tickers and 5 features made 28 upstream
  calls on the first run and 0 on the rerun.
- `store/validate.py` adds on-demand flags that never change the data: impossible OHLC
  bars, duplicate dates, missing trading days against SPY, >40% jumps that no split
  explains, and runs of 5+ identical closes.
- Bug fixed in review before the commit: a request lying entirely after the last
  complete session returned months of extra rows (68 instead of 3 in the repro).

## 5. v0.9.1 — options-chain fix found by the probe

- **Bug:** the options contracts endpoint applies `expired` relative to `as_of`, not to
  today. For AAPL as of 2019-07-01 (expiries 2019-07-02 to 07-19), `expired=true`
  returned 0 contracts and `expired=false` returned 48.
- The code always sent `expired=true` for past dates, so every historical earnings event
  got an empty chain and was dropped from the PEAD table. This predates v0.5.0, so it was
  on `main` too.
- **Fix:** one `expired=false` query. The probe now tests the flag directly. After the
  fix, the probe's options check returns 628 contracts, and option prices come back
  normally (open-close and daily bars).
- The probe results were recorded in `OPEN_QUESTIONS.md` and `docs/ROADMAP.md`.

## 7. v0.10.0 — as-of CIK lookup

- `MassiveSource.ticker_details(ticker, date=...)` and `MassiveSource.as_of_cik`. A 404
  or a record without a CIK returns None.
- `build_pead_panel` now uses `massive_cik_resolver` by default when it builds its own
  Massive sources, and falls back to SEC's current ticker map when Massive has no record.

## 8. Known limitations

- **Holding-company re-registrations** (`OPEN_QUESTIONS.md` item 34): Massive returns the
  successor CIK (Disney on 2018-06-01 → 1744489, whose filings start in 2019) or no
  record (GOOGL in 2015), so earnings filed under a predecessor CIK are missed. They
  are never attached to the wrong company. The fix is a per-date CIK map (Phase 4).
- **SUE timing** (item 29): `eps_filed` can be after the event date.
- **Raw store** (items 30–32): dividends are saved only on the raw basis; a bar the
  vendor publishes late inside an already-saved range isn't re-fetched; vendor
  corrections to history aren't detected except for splits. `RawStore.invalidate()`
  forces a re-download.
- **Validation thresholds** (item 33) are heuristics: real crashes and large special
  dividends also trip the jump flag.
- **VIX** isn't on the current plan. **Flat files** and **FRED** are untested. SEC calls
  still use the placeholder User-Agent (not blocked so far).
