# v0.11.0 — membership security identity

## Summary

`membership/identity.py` resolves the one-id-per-ticker-interval
security_ids that `refresh` derives into durable securities: renames
(FB→META, ANTM→ELV) and leave-and-rejoins (AMD, KDP) merge into one
security, while reused tickers (two different Dow companies) stay apart.
Every upstream lookup is stored in committed evidence tables, so
`--offline` rebuilds the tables byte for byte with zero network.

Build: `python -m data_universe.membership.identity` online;
`--offline` to audit; `--dry-run` to report without writing; `--refetch`
to refresh every consulted key once.

## Evidence model

Three committed evidence tables carry every upstream lookup the resolver
consulted: `identity_evidence.csv` (Massive `?date=` records, 3,644 rows),
`cik_evidence.csv` (SEC registrant summaries, 992 rows), and
`cik_ticker_evidence.csv` (Massive tickers-for-CIK lists, 76 rows). Online
runs fetch missing keys only, checkpoint the evidence union every 200
fetches, and write the tables atomically on success; a crash flushes
whatever was fetched so the next run resumes. `--offline` is the audit:
zero network, and the committed CSVs are reproduced byte for byte —
anything else means the evidence and the tables disagree.

## Resolution rules

- **Probing**: each (sub-)interval's first and last ok record is found by
  probing at offsets 0/7/30/90 days inward from its ends (clipped to
  Massive's CIK coverage floor, 2003-09-11).
- **Trusted CIKs**: a record's CIK counts only when its registrant name
  matches the SEC name or a former name for that CIK (token matching in
  `names.py` — suffixes, abbreviations, spaced initials, hyphen variants,
  one-char typos). Untrusted CIKs (XRAY→Danaher, LLL→JetBlue) are treated
  as absent everywhere and reviewed as `cik_name_mismatch`.
- **CIK segments**: when the endpoint facts carry differing trusted CIKs,
  the switch date is bisected to the day (up to `MAX_CIK_SWITCHES` nested
  switches); single-sided trusted CIKs cover the whole interval.
- **Symbol discovery**: when upstream's symbol has no trusted CIK but the
  interval's end fact does, the walk starts at the bisected takeover date
  and goes backwards through `tickers_for_cik` to the symbols that CIK
  traded under. Guards: more than one candidate requires a FIGI match,
  and a candidate that is another interval's ticker during the proposed
  span is ambiguous (`symbol_discovery_ambiguous`). Vendor gaps end the
  walk but keep the segments found; uncovered prefixes stay under the
  upstream symbol. Discovered segments write `ticker_history` rows with
  source `massive`. The mirror case (both ends trusted, different CIKs)
  only proposes an override as `symbol_reassigned` — never applied.
- **Splits**: a `split` override cuts a ticker interval at a
  change-of-company date into independently-resolved sub-intervals keyed
  `(ticker, sub_start)`; `membership_intervals` partitions accordingly
  and refresh preserves inside-interval map rows.
- **Linking**: `figi_link` needs A.end ≤ B.start with equal non-null
  composite FIGIs; `cik_link` needs touching intervals, equal CIKs, unique
  candidates on both sides and no FIGI contradiction; `link`/`unlink`
  overrides apply manually and suppress the pair's review rows. Any merge
  that would put overlapping intervals in one security is rejected.
- **Ids**: a security's id is its earliest interval's `<ticker>-<YYYYMMDD>`.

## Review and overrides

`identity_review.csv` kinds: `symbol_not_found`,
`cik_change_within_interval`, `too_many_cik_changes`,
`ambiguous_cik_link`, `same_cik_figi_mismatch`, `rejoin_unconfirmed`,
`link_would_overlap`, `cik_starts_late` (massive segment starting >30d
before the registrant's first filing), `cik_no_earnings_filings`
(massive-segment CIK that never filed an 8-K Item 2.02 — dormant or
subsidiary registrant, or an FDIC-filing bank),
`cik_name_mismatch` (vendor name ≠ SEC names, CIK ignored),
`symbol_discovery_ambiguous`, `symbol_reassigned` (proposal only).

`identity_overrides.csv` (human-owned, tools never write it) takes
`link`, `unlink`, `cik`, `symbol`, `split`, `ack`. This release curated
135 rows: 74 `ack`, 25 `cik`, 22 `symbol`, 7 `split`, 7 `link`, including:

- splits: CB 2016-01-19, T 2005-12-01, AGN 2015-03-18, IR 2020-03-02,
  FOX/FOXA 2019-03-19, CPRI 2018-09-19;
- links: IR↔TT, LB↔BBWI, KDP↔KDP (leave-and-rejoin), ARNC↔HWM,
  KORS↔CPRI, DISCA↔WBD, HRS↔LHX;
- retroactive symbols: ES←NU, JEF←LUK, TPR←COH, GHC←WPO, LB←LTD,
  BHGE←BHI, GOOGL←GOOG, AABA←YHOO, KDP←DPS, WYND←WYN, DXC←CSC,
  ARNC←AA/HWM, WBA←WAG, UAA←UA, L←LTR, MS←MWD, WM←WMI, SAF←SAFC,
  TT←ASD;
- predecessor/dormant CIK fixes: DIS, GOOGL, CCE, WRK, LLL, AABA, AGN,
  and the dormant registrants AET, BCR, HRS, RTN, TWX, EXPE, IRM, MWV,
  HCA, AKS, LVLT, DISCA/DISCK (to 1437107), T part 1.

## PEAD resolver fix

`massive_cik_resolver(source, edgar_source)` now runs the same vendor-name
check on the record's CIK: XRAY's Massive record carries Danaher's CIK
and LLL's carries JetBlue's, so a v0.10.0 panel would have attached the
wrong company's 8-Ks; the check falls back to `sec_current` instead. Cost:
one `registrant_summary` call per distinct resolved CIK (cached).
`build_pead_panel` passes its edgar_source when wiring the default
resolver.

## Known limits

- CIK coverage starts 2003-09-11: earlier periods get no as-of evidence.
- Discovery can't recover symbols missing from `tickers_for_cik` (SPGI's
  MHP prefix before 2013, ANTM's ATH before WLP's 2004 listing) — the
  uncovered prefix stays under the upstream symbol as `membership`.
- The name check is a heuristic: false positives are triaged by
  overrides/acks (GE's 2024 rename, T part 1's 'A T & T CORP (NEW)'), and
  false negatives are possible when a wrong CIK's registrant name is
  similar (DISCA's dormant 1024333 was caught by the Item 2.02 flag, not
  the name check).
- `cik_no_earnings_filings` is flag-only — it doesn't change trust, and
  FDIC-filing banks (FRC, SBNY) legitimately have no SEC 8-Ks.
- Folded/duplicated upstream lines (item 40): the acquirer's earlier
  index membership is missing upstream, so member counts in those
  periods can be off by one.
- SUE split factors still use the current symbol until 4b wires
  `ticker_history` into the panel.
