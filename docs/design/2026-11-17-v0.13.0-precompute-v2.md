# v0.13.0 — precompute v2

## Summary

`precompute()`/`load_feature()` now write versioned, per-key derived
datasets under `<out_dir>/<name>/<fingerprint>/` instead of one
unversioned `<name>.parquet` per feature. Reruns compute only uncovered
gaps, labels write only mature rows, recomputing a range deletes stale
values (NaN tombstones), and generic datasets share the same machinery
via `precompute_dataset`/`load_dataset`.

## Design

- `store/derived.py` `DerivedStore` — modeled on `RawStore`: one
  `dataset.json` manifest + `<key>.parquet` + `<key>.coverage.json` per
  (name, fingerprint, key); atomic temp+`os.replace` writes; fcntl key
  locks; `replace_range` drops-then-adds inside a date range;
  `invalidate` deletes keys or subtracts ranges from data and coverage
  records (split, metadata kept).
- Fingerprint — `sha256` of a canonical spec dict: `schema_version`,
  `name`, `kind`, `code_version` (the registered `version=`),
  `horizon_trading_days` (0 for features), `source_family`,
  `conventions` (`ADJUSTMENT_CONVENTION`, `DIVIDEND_CASH_BASIS`) and
  `params` — the function's *explicit* keyword parameters only, valued as
  passed or defaulted. `**kwargs`-absorbed values don't fingerprint.
  `canonical()` is JSON-safe and never reads object attributes beyond a
  callable `precompute_fingerprint()` — secrets can't leak into
  `dataset.json`.
- Run semantics — per (name, key): final cap `C` = `min(end,
  _last_complete_date())` for features, `h` sessions earlier for labels
  (`horizon_trading_days`) and datasets (`final_lag_sessions`), using one
  lazily-built session calendar per call. Gaps of `[start, C]` not in
  coverage are computed (`force=True` recomputes all of it); `end > M`
  adds a provisional tail that is written but never covered. Compute
  extends `h` sessions past the gap end for label maturity, then rows
  outside `[a, b]` are dropped. `replace_range` is the tombstone:
  recomputed NaNs delete stored values.
- Loading — `load_feature`/`load_dataset` pick the single version
  matching the current registry spec plus `version=`/`source=`/`params`
  filters; ambiguity raises. Unversioned pre-v0.13 `<name>.parquet`
  files still read with a `UserWarning`.

## Behavior changes

- File layout: `<name>.parquet` -> `<name>/<fingerprint>/<key>.parquet`.
- Reruns skip covered pairs entirely (`report.skipped`) — zero source
  calls for features; labels cost one SPY calendar call per run unless a
  `StoreBackedSource` serves it.
- Labels only write rows whose full horizon is final; coverage ends at
  the cap, and later runs fill newly-mature rows.
- `start > end` raises `ValueError` (was silently empty before).
- `PrecomputeReport` gains `skipped` and `versions`; keys stay
  `(key, name)`.
- Multi-column features store `[date, ticker, *columns]`; a column change
  inside one version fails with "bump the version".

## Migration

Legacy `<out_dir>/<name>.parquet` files remain readable through
`load_feature` with a `UserWarning`; recompute with `precompute()` to get
a versioned dataset, then `invalidate(name)` to drop the legacy file.

## Tests

`tests/test_store_derived.py` (11) covers the store; `tests/test_precompute.py`
(35+) covers layout, skip/incremental/tombstone/force, fingerprints and
version selection, feature_kwargs, label caps, provisional tails,
multi-column features, invalidate/status, legacy fallback, resume,
concurrency, failure atomicity, and `precompute_dataset` incl. the
secrets-in-params case. Registry `version=`/`horizon_trading_days=`
validation and the two `precompute_fingerprint()` methods are tested in
the registry/source test modules. Review found and fixed two regressions:
builder index alignment in `_normalize_result` (filtered/string indexes
misaligned dates) and the provisional start preceding `S` when the whole
window was past L.

## Live check (2026-11-17)

Real Massive key: AAPL+MSFT × `ret_1d`/`rv_cc_21d`/`beta_ols_60d`/
`fwd_ret_15d` over 2025-01-02..2025-06-30 into a temp `processed/` +
`raw/` root — all 8 pairs computed, no failures. The rerun behind a
counting `MassiveSource` made **zero upstream calls**, all 8 pairs
reported `skipped="up to date"`, and `load_feature` output was identical
for all four names. A second check (`ret_1d` AAPL 2026-10-01..2026-11-17)
ended coverage exactly at L=2026-11-16 with one provisional row written
on 2026-11-17 (past L, uncovered).

## Known limits

See `OPEN_QUESTIONS.md` items 42-46: the PEAD event table isn't cached
(hindsight columns + options cost), no cross-feature dependency reuse,
`**kwargs` values aren't fingerprinted, helper changes need a manual
`version=` bump, and labels pay one calendar call per run.
