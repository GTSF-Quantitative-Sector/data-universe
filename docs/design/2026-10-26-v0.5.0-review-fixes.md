# Design: v0.5.0 correctness fixes and membership refresh

**Status:** Implemented on branch `ethan` (v0.4.0 → v0.5.0)
**Date:** 2026-10-26
**Author:** Ethan Lam

## 1. Context

A full read-through of `data_universe` v0.4.0 found that tests and lint were green (359
tests), yet several code paths returned wrong data **silently** or crashed on ordinary
inputs. The three downstream projects (intraday beta, VRP, PEAD) would have inherited these
errors without noticing, which defeats the purpose of a shared library. This change fixes
them, adds a maintenance path for the vendored S&P 500 membership tables, and updates the
docs to match the code.

## 2. Goals and non-goals

**Goals**

- Wrong data should either become correct or fail loudly. Never return a plausible wrong
  value without an error.
- Keep public signatures backward compatible where possible. Any intentional behavior
  change is listed in §5.
- Give the vendored membership data a reproducible, validated refresh path.
- Make the fake market deterministic so tests and examples are reproducible.

**Non-goals**

- **Corporate identity resolution** (linking FB → META, AMD leave/rejoin, AAL ticker
  reuse). This needs curated corporate-action data and human review of ~1,262 mappings,
  and must not be made up in code. Tracked as `OPEN_QUESTIONS.md` item 18.
- Building the `Ticker` facade, `FlatFilesSource`, or single-name IV30.
- Strictly regular-hours hourly bars built from minute aggregates.

## 3. Design decisions

### 3.1 Warm-up anchoring on non-session starts (`features/registry.py`)

**Problem:** `compute()` called `calendar.shift_sessions(index, start, -n)`, which does
`get_loc(start)`. That raises `KeyError` when `start` is a weekend or holiday. The README's
own `"2024-01-01"` example failed against real data.

**Decision:** Anchor on `session_index[searchsorted(start, "left")]`, the first session on
or after `start`, then shift back by the warm-up. The result is still sliced to exactly
`[start, end]`. A weekend start therefore produces the same output as the following
Monday.

### 3.2 Hourly regular-hours filter (`sources/base.py`)

**Problem:** The filter kept stamps between 09:30 and 16:00 inclusive. Polygon/Massive stamp
aggregates at the **start** of their window, so this dropped the 09:00 bar (which holds
9:30–10:00 trading) and kept the 16:00 bar, which is entirely after-hours.

**Decision (user-selected):** Keep a bar iff its `[stamp, stamp + bar_minutes)` window
overlaps `[09:30, 16:00)`. For hourly bars this keeps 09:00–15:00 (7 bars per session).
`filter_regular_hours(bars, bar_minutes=60)` is generic over bar size.

**Trade-off:** The 09:00 bar includes 9:00–9:30 pre-market trades. This is accepted and
documented (`OPEN_QUESTIONS.md` item 19).

**Alternatives rejected:** (a) Keep 10:00–15:00 only, which drops the first half hour of
the session entirely. (b) Rebuild hourly bars from 30-minute bars. That is correct but adds
request volume and complexity, and nothing needs it yet.

### 3.3 Risk-free rate and excess returns (`features/library.py`, `precompute.py`)

**Problem:** `ret_excess_1d` silently fell back to raw returns when no `rate_source` was
given. `precompute()` had no way to pass one, so every precomputed `ret_excess_1d` was
identical to `ret_1d`. Beta and alpha also used raw returns, while `PLAN.md` §7 specifies
excess returns.

**Decision (user-selected, "excess when given"):**

- `ret_excess_1d` raises `ValueError` without a `rate_source`.
- `beta_ols_*` and `alpha_ols_*` accept an optional `rate_source`. When one is given, they
  subtract `log1p(rf)` from both the asset and market log returns before the rolling OLS.
  Without one they keep the raw-return behavior, as a compatibility path.
- `_daily_rf` fetches from 14 calendar days before `start`, then forward-fills onto the
  session index, so bond-market holidays carry the previous rate instead of 0. Leading
  dates with no prior observation stay NaN rather than being filled with an invented value.
- `precompute(..., **kwargs)` forwards extra kwargs, such as `rate_source`, to `compute()`
  for every pair.
- `FakeRateSource` provides a constant-rate source for tests and for users without a key.

### 3.4 Membership keys (`membership/grid.py`)

**Problem:** Grid columns are provisional `security_id` values such as `AAPL-19960102`.
Calling `mask_like()` on a ticker-column panel returned an all-False mask without any
error.

**Decision:**

- Add `by="security_id" | "ticker"` to `membership_grid`, `mask_like` and `members_on`.
  `by="ticker"` builds directly from `ticker_intervals.csv`, keyed by upstream's symbol
  for each interval.
- With `by="security_id"`, `mask_like` raises `MembershipError` when **none** of the
  frame's columns match, because that almost always means the columns are tickers. With
  `by="ticker"`, zero matches is legitimate (the panel has no members) and does not raise.
- The default stays `security_id` for backward compatibility. The docs warn not to persist
  these IDs.

### 3.5 Deterministic fake market (`sources/fakes.py`)

**Problem:** Seeds came from `hash()`, which is salted per process, so values changed
between runs. Prices also depended on the requested window's start date.

**Decision:** Seed from SHA-256 of `"{seed}|{ticker}|{freq}"`. Generate each series from a
fixed epoch (`1990-01-01`) through `end`, then slice from the business-day offset of
`start`. The same date always has the same price, in any process. A `start` before the
epoch raises `ValueError`. Raw hourly bars now span 08:00–16:00 (9 per session), like
vendor aggregates. `FakePolygonSource.hourly_bars` filters them the same way the real
source does.

**Known cost:** Each call generates the series from 1990 onward. This is negligible for
tests. If the fake is used for heavy panels, cache the cumulative series per
`(seed, ticker, freq)`.

### 3.6 PEAD event table (`events/earnings.py`)

- `sigma_pre_daily` now uses 31 closes → 30 log returns. The window start shifted from
  `-29` to `-30` sessions.
- A missing ticker bar on `day0` or `day1` (for example a halt) skips that one event
  instead of aborting the whole ticker.
- `acceptanceDateTime` (ISO UTC) is converted to America/New_York before normalizing, so a
  20:30 ET filing lands on the correct ET date.

### 3.7 EDGAR historical filings (`sources/edgar.py`)

**Problem:** Only `filings.recent` was read. That covers roughly the last year or ~1,000
filings, so older earnings 8-Ks from heavy filers were silently missing.

**Decision:** Also fetch every page listed in `filings.files`, using the same User-Agent,
then combine, deduplicate, and sort. The response shape was verified against live
data.sec.gov.

### 3.8 Options daily close (`sources/polygon_options.py`)

A 404 `NOT_FOUND` from `/v1/open-close` means the contract did not trade that day. It now
returns `{"close": NaN, "volume": 0.0}`, which the event table flags as `is_stale`, instead
of raising. A 200 response with no `close` returns NaN (it previously returned 0.0, which
looked like a valid price). Other HTTP errors still raise.

### 3.9 FRED error hygiene (`sources/fred.py`)

FRED requires `api_key` as a query parameter, and `requests` errors include the full URL.
Transport and HTTP failures are now re-raised as `DataSourceError` naming the series and
the HTTP status or exception class. The raise happens **outside** the `except` block, so
`__context__` is `None` and the key never appears in tracebacks.

### 3.10 Atomic, serialized precompute writes (`precompute.py`)

The read-merge-write in `_upsert_parquet` runs under an exclusive `fcntl.flock` on
`.<name>.parquet.lock`. The output is written to a temp file in the same directory and
moved into place with `os.replace`. On failure the temp file is removed and the previous
file is left unchanged. On Windows there is no lock, but the write is still atomic. The
lock file is left in place on purpose; deleting it would reopen a race.

### 3.11 Membership refresh tool (`membership/refresh.py`)

`python -m data_universe.membership.refresh [--ref REF] [--dry-run]`:

1. Resolves `REF` to a commit SHA through the GitHub API, then downloads the upstream CSV
   at that pinned SHA.
2. Validates the file: the header must be exactly `date,tickers`, dates must be canonical
   and strictly ascending, there must be no empty tickers, and the latest snapshot must
   have 480–520 members.
3. Derives intervals. It keeps existing `security_map`/`security_master` rows for
   intervals that still exist, so reviewed work survives. New intervals get provisional
   IDs. Reviewed rows that would be dropped are reported as warnings.
4. Writes the tables to a staging directory and validates them with
   `intervals.membership_intervals` (no unmapped or overlapping intervals) **before**
   replacing any committed file.
5. Writes the manifest with provenance (commit SHA and date, file SHA-256, row counts) and
   `verified_through` set to the run date in UTC.

Verified to reproduce the committed `ticker_intervals.csv`, `security_map.csv` and
`security_master.csv` byte-for-byte at the pinned upstream commit `a2430f2`. Provenance and
the audit procedure are in `data_universe/membership/tables/sp500/README.md`.

## 4. Testing

The suite grew from 359 to 409 tests, all offline (fakes and mocked HTTP). New coverage:

- weekend and holiday starts
- hourly and 1-minute overlap filtering, including timezone conversion
- cross-process determinism (subprocess runs with different `PYTHONHASHSEED`)
- window-independent prices
- excess-return math, rate forward-fill, and the excess-return regression
- `precompute` kwarg forwarding
- concurrent writers and failed-write atomicity
- the sigma window, missing-bar skip, ET date mapping, and stale options
- EDGAR paging
- options 404 handling
- FRED key-leak checks on the message, `__context__`, and the formatted traceback
- `by="ticker"` grid/mask/members and loud zero-match failure
- refresh parsing, validation, reviewed-mapping preservation, staging rollback, dry run,
  and CLI

## 5. Behavior changes for consumers

| Area | Before | After |
|---|---|---|
| `ret_excess_1d` without `rate_source` | Raw returns | `ValueError` |
| `beta_*`/`alpha_*` with `rate_source` | Not supported | Excess-return regression |
| `hourly_bars` stamps | 09:30–16:00 (wrong) | 09:00–15:00 |
| `FakeMarket` values | Varied per process/window | Fixed. All fake prices changed once. |
| `mask_like` (security_id, 0 matches) | All-False | `MembershipError` |
| `daily_close` on 404 | `HTTPError` | `{"close": NaN, "volume": 0.0}` |
| `daily_close` missing `close` | `0.0` | `NaN` |
| FRED request failure | `requests.HTTPError` (URL incl. key) | `DataSourceError` (no key) |
| PEAD `sigma_pre_daily` | 29 returns | 30 returns |
| `earnings_8k_filings` | Recent page only | Full history |

Anything precomputed or cached under v0.4.0 for `ret_excess_1d`, hourly features, or PEAD
sigma should be recomputed. Clear the disk cache tier if one is configured
(`MAINTENANCE.md` §6).
