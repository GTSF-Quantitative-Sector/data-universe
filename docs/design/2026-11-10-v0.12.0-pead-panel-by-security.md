# v0.12.0 — PEAD panel by security

## Summary

`build_pead_panel` now processes index membership by `security_id` from
the committed identity tables instead of one CIK per upstream ticker
interval. Mid-interval re-registrations (MDT 2015, CI 2018, AVGO),
predecessor CIKs (DIS, GOOGL) and retroactive upstream symbols
(SPGI←MHFI, BKNG←PCLN) all reach the event table.

## What changed

- `membership/intervals.py` — new `membership_pieces(index_id)`: one row
  per (sub-)interval, uncoalesced, with default `<ticker>-<YYYYMMDD>` ids
  when no security_map row exists.
- `events/earnings.py` — `build_pead_panel` iterates securities in sorted
  id order; `PANEL_EVENT_COLUMNS` adds `security_id`; report keys
  (`succeeded`/`sue_failed`/`cik_gaps`) are security ids; `failed` holds
  per-security errors and requested-ticker misses; new
  `PeadPanelReport.cik_gaps` flags CIK rows with >=180d of member overlap
  and no home 8-K Item 2.02.
- `fundamentals/sue.py` — `quarterly_sue(predecessor_ciks=...)` pulls
  first-reported facts across all of a security's CIKs; the output `cik`
  is the chosen fact's CIK.

## Identity path

For a security with `cik_history` rows: per-date CIKs from
`cik_segments` over the calendar window (or a single `explicit` row from
`cik_overrides`); per-date vendor symbols from `symbol_segments` (or the
pieces' own tickers when no `ticker_history`). Each distinct CIK's Item
2.02 filings are fetched once; a filing counts when its ET filing date
falls in a home span widened by `_CIK_BOUNDARY_SLACK_DAYS` (100 days)
across a CIK boundary — so both sides of a switch keep their filings.
Filings dedupe per filing date (home CIK first, then earliest
acceptance), covering co-filed accessions and same-day two-registrant
pairs. Every event's `ticker` is the symbol covering its filing date;
`cik_source` is `cik_history` or `explicit`.

The fallback path (no `cik_history` — unresolved `new_default`
securities) keeps the pre-v0.12.0 per-interval CIK resolution.

## Known limits

The boundary-slack heuristic (item 41): a former registrant filing its
own Item 2.02 within 100 days of a switch on a different day than the
successor would add a duplicate event. `tickers=` selects securities via
candidate pieces plus `ticker_history` rows, so `tickers=["META"]`
includes FB-era events.
