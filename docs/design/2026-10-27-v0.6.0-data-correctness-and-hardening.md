# Design: v0.6.0 data correctness and hardening

**Status:** Implemented on branch `ethan` (v0.5.0 → v0.6.0)
**Date:** 2026-10-27
**Author:** Ethan Lam

## 1. Context

v0.5.0 fixed about a dozen silent errors, but a full read for the roadmap found two more
that downstream projects (PEAD, the GNN ranker) would have inherited:

1. **Dividends were left out of every adjusted series.** `daily_bars`/`hourly_bars` sent
   the vendor's `adjusted=true`, which is **split-only**. README, CONTRACTS and
   `sources/base.py` all promised split+dividend adjustment, so every return, volatility,
   beta and label was silently missing dividend yield (~1.8%/yr for the S&P 500).
2. **The PEAD ATM straddle picked the wrong strike after any later split.** `spot` came
   from the split-adjusted close, but historical option strikes are on the raw
   (as-traded) basis — AAPL's 2020 4:1, NVDA's 2021 and 2024 splits, TSLA, GOOGL/AMZN 20:1
   all shift the "ATM" strike far from the money the event actually saw.

On top of that: subscription entitlements were unknown (does the plan include indices?
options? flat files? minute bars?), only HTTP 429 was retried (a 5xx or timeout silently
failed a precompute pair), 401/403 couldn't be told apart from other errors, and EDGAR had
no rate limit, no retries, a placeholder User-Agent, and re-downloaded the
ticker→CIK map for every lookup.

This change fixes the two silent errors, hardens every HTTP path, and adds an opt-in
entitlement probe so the later roadmap phases can be scoped from facts instead of
guesses. The roadmap itself is `docs/ROADMAP.md`.

## 2. Goals and non-goals

**Goals**

- `daily_bars`/`hourly_bars` are genuinely total-return adjusted; real (raw) price levels
  stay available separately. Nothing claims dividends are included unless they are.
- Price *levels* that interact with the outside world (option strikes, dollar volume)
  use raw prices; return/volatility *ratios* use total-return prices.
- Transient failures retry; entitlement failures raise a distinct error; EDGAR stays
  within SEC's 10 requests/s and sends a configurable descriptive User-Agent.
- One opt-in command answers "what does our plan actually include" without leaking keys.
- All tests stay offline; CI needs no secrets.

**Non-goals** (tracked in `docs/ROADMAP.md`)

- PEAD event-table v2 (`announce_timing`, `reaction_session`, straddle prices, implied
  move) — additive columns, Phase 2. `day0` semantics are unchanged here.
- The durable raw store / flat-file ingest (Phase 3), identity resolution (Phase 4),
  new datasets: XBRL, earnings calendar, news, short interest (Phase 7).
- Single-name IV30, minute bars, strictly regular-hours hourly bars.

## 3. Design decisions

### 3.1 Total-return adjustment (`sources/adjust.py`, `sources/polygon.py`)

**Problem:** the vendor's `adjusted=true` multiplies pre-split prices by the split ratio
but does **not** reinvest dividends. The docs said otherwise.

**Decision:** build the adjusted series ourselves from three cached primitives:

- `daily_bars_split_adjusted` — `adjusted=true` (reuses the v0.5.0 `daily_bars` cache
  namespace; existing disk entries hold exactly this series),
- `daily_bars_raw` — `adjusted=false` (real traded prices and share counts),
- `dividends(ticker, start, end)` — `/v3/reference/dividends`, paginated, locally
  re-filtered to `[start, end]` (the request params only narrow the download).

`daily_bars` = `apply_total_return(split_bars, dividend_factors(closes, dividends))`
with the backward multiplicative convention `f_e = 1 − D_e / C(prev)`, summed over all
dividend records sharing an ex-date. `hourly_bars` applies the same per-session factors
to regular-hours hourly bars. `index_daily_bars` is unchanged (indices pay no dividends).

**Anchoring:** only ex-dates strictly after the first bar and on/before the last are
applied, so the last bar equals the split-adjusted price. Levels are therefore
window-dependent by design and comparable only within one call; every ratio is
window-independent. Consumers needing real price levels use `daily_bars_raw`
(`OPEN_QUESTIONS.md` item 21).

**Cash basis:** `dividend_factors` divides `cash_amount` by raw closes when
`DIVIDEND_CASH_BASIS == "raw"` (the assumed vendor convention — declared amounts), or by
split-adjusted closes otherwise. One constant flips the whole pipeline if the probe's
`dividend_cash_basis` finding says otherwise (`OPEN_QUESTIONS.md` item 20). This is why
v0.6.0 should not be merged until the probe is run once with real keys.

**Loud failures:** a non-USD dividend record, or a factor outside (0, 1) (dividend ≥
prior close, or non-positive amount), raises `DataSourceError` rather than adjusting
silently. Spin-offs, stock dividends and rights issues are not adjusted — documented
limitation.

**Cost:** three cached requests per (ticker, window) instead of one, until the Phase 3
store exists. The total-return composite itself is not cached (it's a cheap pure
transform of cached inputs, and caching it would make the answer depend on which window
was asked first).

`DataSource.daily_bars_raw` is non-abstract and raises `NotImplementedError` with a
pointer, so existing custom sources still construct but fail loudly only if a
raw-price feature is actually requested.

### 3.2 Fakes model corporate actions (`sources/fakes.py`)

`FakeMarket` gains `dividend_yield=0.004` (per quarter) and `splits: dict | None`
(ticker → `[(date, ratio)]`). The generated price process `P` stays the **total-return**
series, so `daily_bars` output is unchanged and all v0.5.0 fake-based tests keep their
values. Split-adjusted `S = P·K(t)` (product of `1 − y` over ex-dates ≤ t), raw
`R = S·M(t)` (product of split ratios after t; raw volume is `volume/M(t)`), and
`dividends()` reports `D_e = y · R(prev)` on the raw basis, matching
`DIVIDEND_CASH_BASIS = "raw"`. Ex-dates fall every 63rd session from the epoch with a
SHA-256 per-ticker phase; `I:` tickers and `dividend_yield=0` pay nothing. Everything is
built from the epoch and sliced, so values remain window-independent.
`apply_total_return(S, dividend_factors(R.close, D)) / P` is constant to ~1e-12 — the
real adjustment path is round-trip-tested against a market whose ground truth is known.

### 3.3 Raw dollars for liquidity (`features/library.py`)

`dollar_volume_1d` is now raw close × raw volume — dollars actually traded — and
`adv_usd_20d` inherits it. Both are price *levels*; split- or dividend-adjusted inputs
would misreport pre-split liquidity by the cumulative adjustment factor.

### 3.4 PEAD raw spot and filtered chain (`events/earnings.py`, `options/chain.py`)

- `spot` for ATM strike selection is the **raw** day-0 close — historical option strikes
  are raw, so a split-adjusted spot picked the wrong contract for any event before a
  later split (the second silent error; regression test plants a 4:1 split).
- `adv_usd_pre20`/`adv_usd_day0_day1` use raw close × raw volume.
- `sigma_pre_daily` keeps using total-return closes (a ratio).
- An event is skipped when `day0`/`day1` is missing from **either** the adjusted or the
  raw frame.
- `chain.as_of` forwards `expiration_gte/lte`, `strike_gte/lte` filters: the PEAD query
  now asks for expiries in `(day0, day0 + 40d]` and strikes within ±20% of spot instead
  of the whole chain (monthly expiries are never more than 35 days apart). Sources that
  don't accept the kwargs still get the 2-argument call.

### 3.5 Options source fixes (`sources/polygon_options.py`, `sources/massive.py`)

- `contracts_as_of(underlying, as_of, expiration_gte=None, expiration_lte=None,
  strike_gte=None, strike_lte=None, contract_type=None)` maps filters to the vendor's
  `expiration_date.gte/.lte`, `strike_price.gte/.lte`, `contract_type` params.
- `expired=true` alone misses contracts still listed today; when the expiry window can
  reach today (`expiration_lte` is None or ≥ `_today()`, patchable in tests) a second
  `expired=false` query is unioned in and deduplicated (`OPEN_QUESTIONS.md` item 22).
- All URLs go through `self._base_url()`, so `MassiveOptionsSource(MassiveSource,
  PolygonOptionsSource)` — new — serves options calls from `api.massive.com` with the
  Massive key by MRO alone; no duplicated logic.

### 3.6 Shared retries and entitlement errors (`sources/http.py`, `sources/base.py`)

`get_with_retries(session, url, *, params, headers, timeout, max_retries,
backoff_seconds, throttle)` retries 429/500/502/503/504 and connection/timeout errors
with doubling backoff; `time.sleep` is looked up at call time so existing monkeypatches
keep working. Persistent 429 raises `RateLimitedError`; persistent 5xx/transport failure
raises `DataSourceError`. Messages name only the URL **path** — never a query string —
so nothing secret can leak that way.

`EntitlementError(DataSourceError)` — new — is raised by `PolygonSource._get` (inherited
by `MassiveSource`, both options sources) on 401/403: bad key or a dataset the plan
doesn't include, distinct from an empty result and from a flaky network.

### 3.7 EDGAR fair access (`sources/edgar.py`, `config.py`)

- A process-wide throttle (`_throttle`, module lock + `time.monotonic`) spaces requests
  ≥ 0.11s apart — ≤ 9/s against SEC's 10/s cap — and runs before every attempt.
- Requests go through `get_with_retries`; a 403 raises `DataSourceError` at once
  explaining the User-Agent and rate-limit causes.
- The User-Agent resolves as constructor arg → `config.get_user_agent()` (env
  `DATA_UNIVERSE_USER_AGENT`, YAML `user_agent`) → placeholder + a one-time
  `UserWarning` telling the operator what to set. `IndexUniverseSource` takes the same
  precedence (no warning — its default is documented, not placeholder-shaped).
- `ticker_map()` (`@cached("company_tickers")`) downloads `company_tickers.json` once
  per process instead of once per `get_cik` call. It still lists only *current*
  tickers — FB and other renamed/delisted names need an explicit `cik=`; the probe's
  as-of ticker-details check scopes Phase 4's fix.

### 3.8 Entitlement probe (`probe.py`, `python -m data_universe.probe`)

Opt-in, never in CI, always exits 0 unless arguments are bad. Hits each endpoint this
library relies on (or plans to) once with real keys — aggs at several timespans/depths,
dividends, splits, ticker details (including `FB?date=2020-06-01`), options contracts
plus pricing of the contract nearest the raw spot, `I:VIX`, EDGAR submissions +
`companyfacts`, FRED series, and `boto3 list_objects_v2` on the flat-files bucket (only
if `boto3` is installed and S3 config exists — lazy import, no new dependency).

Each check records `{check, group, endpoint (path template), path_verified, status,
http_status, rows, detail, findings}`; statuses cover `ok`, `empty`, `not_entitled`,
`not_found`, `path_unverified`, `rate_limited`, `error`, `skipped_no_key`,
`skipped_missing_dep`, `skipped_dependency`. Derived findings answer the loaded
questions: `adjusted_true_is_split_only`, `split_adjustment_applied`,
`dividend_cash_basis` (AAPL 2019-08-09: $0.77 raw vs $0.1925 split-adjusted),
`options_strikes_are_raw`, `fb_as_of_cik_is_meta`, `diluted_eps_has_filed_dates`.

Secrets can't leak: headers are never recorded, endpoints are path templates, FRED goes
through `FredSource` (which strips its URL-borne key from errors). Tests set sentinel
keys and assert they appear nowhere in the JSON or stdout.

## 4. Testing

The suite grew from 409 to 475 tests, all offline. New coverage:

- `adjust.py`: single and same-day-summed dividends, ex-date boundary handling
  (first bar, halted day, after last bar), non-USD and out-of-range factor raises,
  daily and hourly application, volume untouched.
- Source composition: `daily_bars` issues exactly three requests; total-return ratio
  across an ex-date is `raw_e / (raw_{e−1} − D)`; repeat calls hit cache; hourly
  total-return; retry on 503/connection-error, no retry on 403 (`EntitlementError`),
  path-only error messages.
- Fakes: split-adjusted/raw/volume relations, constant total-return ratio, no dividends
  for index tickers, window independence.
- EDGAR: throttle spacing (fake clock), retry on 429/503, the 403 message, single
  `company_tickers` download across lookups, User-Agent precedence and warning, config
  env/YAML handling.
- Options: filter params sent, `expired=false` union only when the window reaches
  today, dedup, `MassiveOptionsSource` on `api.massive.com`, `chain.as_of` filter
  forwarding and 2-argument duck-typing.
- PEAD: ATM strike chosen nearest the **raw** spot under a planted split, raw-dollar
  ADV, filter kwargs forwarded.
- Probe: every status mapping, every finding function, skipped-without-keys/dep,
  AccessDenied → `not_entitled`, sentinel-secret leak checks on JSON and stdout, CLI.

## 5. Behavior changes for consumers

| Area | Before | After |
|---|---|---|
| `daily_bars`/`hourly_bars` | Split-only (`adjusted=true`) | Total-return (splits + cash dividends), window-end anchored |
| `dollar_volume_1d`/`adv_usd_20d` | Split-adjusted close × split-adjusted volume | Raw close × raw volume (real dollars) |
| PEAD `spot`/ATM strike | Split-adjusted close | Raw close — correct strikes pre-split |
| PEAD `adv_usd_*` | Adjusted dollars | Raw dollars |
| PEAD options fetch | Whole chain per event | Filtered: expiries (day0, day0+40d], strikes ±20% of spot; `expired`+`active` union when the window reaches today |
| `contracts_as_of` signature | `(underlying, as_of_date)` | Same + optional `expiration_*`, `strike_*`, `contract_type` filters |
| Vendor 5xx/timeout | `requests.HTTPError`/transport exception, no retry | Retried, then `DataSourceError` (path only) |
| Vendor 401/403 | `requests.HTTPError` | `EntitlementError`, no retry |
| Persistent 429 | `RateLimitedError` (unchanged type) | Same, now shared with EDGAR |
| EDGAR requests | No limit, no retry, placeholder UA | ≤9/s throttle, retries, configurable UA (placeholder warns once) |
| `get_cik` | Re-downloads `company_tickers.json` per call | One download per process |
| `FakeMarket` | No corporate actions | `dividend_yield`, `splits`; `daily_bars` values unchanged |
| Custom `DataSource`s | `daily_bars` + `hourly_bars` | Same, plus optional `daily_bars_raw` (needed by dollar-volume features and PEAD; raises `NotImplementedError` if absent) |
| Requests per bars window | 1 | 3 (split-adjusted, raw, dividends — each cached) until the Phase 3 store |

Adjusted levels are anchored at the window's last bar: compare levels only within one
call; ratios are window-independent. Anything precomputed from returns, volatility or
beta under v0.5.0 shifts slightly once dividends are included — recompute it. The disk
cache needs no manual clear: the composite isn't cached and the primitive namespaces
still hold the same series they did (`MAINTENANCE.md` §6).
