# Open Questions

Every unverified assumption and known implementation gap in this repo, consolidated in one
place. Numbers match `PLAN.md` §9 where that section already numbered an item, so
cross-references from code docstrings stay stable. Items 11-23 are new gaps discovered
during implementation, not present in `PLAN.md` §9. Items 4, 5, 10, 15, 20 and 22 are all
answered by `python -m data_universe.probe` (v0.6.0) — one opt-in run with real keys.

| 16 | Is Wikipedia acceptable as the source of index membership? | Massive publishes index prices but, as far as could be found, no constituent lists, so `sp500`/`dow`/`nasdaq100` are scraped from Wikipedia. | 17 | Does "Nasdaq" mean the Nasdaq-100 or every Nasdaq-listed stock? | Roughly a hundred names versus thousands. | Both are provided: `nasdaq100` (Wikipedia) and `nasdaq_listed` (Massive reference data, primary exchange XNAS, common stock only by default). | Confirm which the research projects want and drop the other from the CLI defaults. |
| 18 | How should membership identity resolution work? | Today every `security_id` is a provisional `<ticker>-<YYYYMMDD>` string — renames (FB → META), leave-and-rejoin (AMD), and ticker reuse (AAL) all read as separate securities, and `ticker_history.csv`/`tail_changes.csv` sit empty. Anything persisting today's ids breaks when real mappings land. | Needs curated corporate-action data plus human review before `security_map`/`security_master` get real identities. Until then, use `by="ticker"` for ticker-keyed panels (upstream's symbol per interval — not always the symbol in use at the time) and don't persist security_ids. | Build `membership/identity.py` in a future phase; `mask_like` already fails loudly (rather than silently returning an all-False mask) when a ticker-keyed panel is passed under the default `by="security_id"`. |
| 19 | Is the start-stamped hourly-bar convention right? | Polygon/Massive stamp aggregates at the window start, so the 09:00 bar returned by `hourly_bars` includes 9:00-9:30 pre-market trades alongside 9:30-10:00 regular-hour ones — slightly contaminated regular-hours data. | **Decided 2026-10-26**: keep a bar iff its `[stamp, stamp + bar_minutes)` window overlaps 9:30-16:00 ET (`filter_regular_hours`), accepting the 30 minutes of pre-market in the 09:00 bar. The alternative — building hourly bars from 30-minute or minute aggregates — is not implemented. | Revisit if a project needs strictly regular-hours-only hourly bars. Cross-referenced from `sources/base.py`. |
| 20 | Is the vendor's dividend `cash_amount` on the raw (as-declared) or split-adjusted basis? | `dividend_factors` divides `cash_amount` by a close on the matching basis; the wrong basis silently scales every total-return factor by the cumulative split ratio. | `adjust.DIVIDEND_CASH_BASIS = "raw"` — vendor docs and the records' lack of an adjustment field suggest declared amounts. One constant flips the whole pipeline, and the fakes follow it automatically. | Run `python -m data_universe.probe`: its `dividend_cash_basis` finding checks AAPL's 2019-08-09 dividend ($0.77 raw vs $0.1925 split-adjusted). **v0.6.0 is release-gated on this check.** Cross-referenced from `sources/adjust.py`. |
| 21 | Where should total-return levels be anchored? | Only the requested range is fetched, so the anchor can't be "inception" — and the choice decides whether adjusted levels are comparable across calls. | **Decided 2026-10-27**: anchor at the window's last bar (it equals the split-adjusted price). Returns and other ratios are identical for any window; levels compare only within one call. Phase 3's store re-anchors at the store's last date, which changes nothing for ratio consumers. | None — documented in `sources/adjust.py` and `CONTRACTS.md`. Revisit only if a consumer needs cross-call levels (use `daily_bars_raw` instead). |
| 22 | What does the vendor's `expired` flag on options contracts actually mean? | `contracts_as_of` used to send only `expired=true`, which misses contracts still listed today — a silent gap for recent events. | Query `expired=true` always, and union in `expired=false` whenever the expiry window can reach today, deduplicating by contract ticker. The exact flag semantics remain unverified. | The probe's `aapl_contracts_as_of_2019` check confirms the endpoint and `as_of` filtering; the union approach is the safe over-fetch until the flag's semantics are documented. Cross-referenced from `sources/polygon_options.py`. |
| 23 | What are the exact paths for the Phase 7 datasets? | Benzinga earnings/estimates, short interest, short volume, Treasury yields and related companies are wanted (`docs/ROADMAP.md` Phase 7) but their Massive REST paths are unconfirmed — guessing them into the probe would report meaningless 404s. | Only long-documented paths are probed today (`/v2/reference/news` is the sole new-data check). Each future check must carry a `doc_url` confirming its path first. | Confirm each path in Massive's REST docs, then add checks to `probe.py` `run_newdata`. |
